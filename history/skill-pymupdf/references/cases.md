# 案例库与排错手册

> 本文件记录真实项目中验证过的参数和踩过的坑。遇到"章位置不对"先读这里。

## 1. 已验证的章图层

| 章 | 幅面 (pt) | 章在图层的 bbox (pt) | 章尺寸 | 距图层右 / 下边缘 |
|---|---|---|---|---|
| 出图章（红色长方形，工程施工/设计出图专用章） | A2 1689.12 × 1195.92 | (1433.3, 517.0)–(1639.2, 596.2) | 205.9 × 79.2 | 49.9 / 599.8 |
| 公章（红色圆形） | A4 594.96 × 840.96 | (248.6, 607.7)–(360.5, 719.5) | ≈112 × 112 | 234.5 / 121.5 |

两者都是**整页透明图层**（PDF 里是一张带 SMask 的大图，例如 7038×4983 px），除章以外全透明。判断方法：`page.get_images(full=True)` 有 smask；`inspect` 显示幅面是标准图幅而彩色 bbox 只占一两百 pt。

**公章为什么也用右下角对齐**：目标是可研/实施方案的 A4 封面，图层与页面同幅，右下角对齐即整页重合，圆章正好压在封面"公司名称 + 日期"处。参考成品也是只在首页有章。

## 2. 混合图幅下章的理论位置（整幅 A2 图层右下角对齐）

图层右下角对齐时，章的绝对坐标 = 页面尺寸 − (49.9, 599.8) 再减去章自身尺寸：

| 页面幅面 | 章 bbox (约) | 距页面右边缘 |
|---|---|---|
| 1689×1196（建筑图封面/内页） | (1433,517)–(1639,595) | 50 |
| 2112×1196（加宽建筑图） | (1856,518)–(2062,594) | 50 |
| 2531×1196（图纸目录页） | (2275,517)–(2481,595) | 50 |
| 1695×1202（结构图） | (1440,526)–(1642,601) | 50 |
| 2117×1202（加宽结构图） | (1861,526)–(2066,601) | 50 |
| 2390×1689 / 2395×1695（加高结构图） | (2134,1010)–(2340,1086) | 50 |

**关键校验指标：不管页面多宽多高，章距页面右边缘恒为 50pt。** 若某一页右距明显变大，说明那一页用了写死坐标或没按页面尺寸定位。

注意 `verify` 是低 dpi 彩色像素采样，实测同一批 9 页的读数会是 47–50pt（±3pt 量化误差），属正常；判断异常看的是"某一页比其它页大几十 pt"，不是 3pt 的抖动。想更精确可加 `--dpi 100`。

## 3. 与参考成品比对的方法

1. 用 `inspect` / `verify` 的彩色像素 bbox 分别量参考件和成果的章位（渲染 dpi 60–150，红像素阈值 r>130 且 r−g>55、r−b>55）。
2. 同一页、同一 `clip` 各裁一张局部图（例：`clip=Rect(1330,460,1689,700)`，dpi 150），拼成上下对比图目视。
3. 已签章成品常是扫描/拼版产物，坐标抖动 ≤4pt（约 1.4mm）属正常，不必强行对齐到小数。
4. 章面文字（单位、行业、证书号）不同不代表盖错章 —— 先确认用户给的章源就是他要的那枚。

## 4. 完整试错记录（不要重蹈覆辙）

| 版本 | 做法 | 结果 |
|---|---|---|
| ① | 整幅 A2 图层**左上原点**对齐 | A2 页正确，但加宽页的章留在原位置，视觉上偏左 → 用户说"靠右下布置" |
| ② | 从 SMask 裁出章本体，贴页面右下角内缩 50pt | 用户："最后两张图还是偏左" —— 被否决，因为破坏了整幅图层的相对关系 |
| ③ | 裁出的章贴纸角内缩 10pt | 章越过图框线、压到图签栏外 |
| ④ | 裁出的章贴齐图框内边线 | 视觉上章跑到最底部，完全不是参考件的样子 |
| ⑤ ✅ | **整幅 A2 图层 1:1 右下角对齐** | 与用户已签章成品逐页比对偏差 ≤4pt，用户确认"可以，按这个把所有的都弄了" |

**教训**：用户说"把图片放到右下角"指的是**整张图片**（章图层的载体），不是"把章抠出来贴到角上"。当章图层幅面等于图纸幅面时，两种理解在标准页上看不出差别，但在加宽页上差别巨大 —— 一定要拿加宽页验证。

## 6. 常见问题

**Q：章源路径读不到（移动硬盘离线 / U 盘没插）？**
先用 `inspect` 找本地缓存的等效章资源。若只有"从同一图层裁出的透明章 PDF"（205.9×79.2pt），可用它与 `--anchor bottom-right --dx -49.92 --dy -599.76` 拼出与整幅 A2 图层右下角对齐**完全等效**的坐标（因为章右/下边距图层边 49.92 / 599.76pt）。要向用户说明章源不是原文件、但同源且结果一致，待磁盘恢复可用原件复核。

**Q：`verify` 报缺章，但肉眼看有章？**
可能是蓝色章（用 `--color blue`）或章是灰/黑色描边（彩色检测不适用）；也可能是页面旋转导致章被盖到可见区外。渲染该页确认。

**Q：`verify` 的 bbox 明显大于章本身？**
图纸里有红色标注线/文字被一起算进去了。改用局部渲染目视，或缩小 `--dpi` 采样步长；不要据此判定章错位。

**Q：盖重复了 / 要换位置？**
不要在原文件上再盖一层。先 `restore --from-dir "<目录>/_未盖章原件" --to-dir "<目录>"` 恢复，再改参数 `apply`。备份已存在时 `apply` 默认不会覆盖，干净原件始终安全。可加 `--check-existing` 兜底：它只检查「预计章位的小矩形」内彩色墨迹占比（默认 ≥4% 判定已盖章），不会像整页检测那样被图纸里的红色标注误触发。自测记录：干净图纸 p0 有红字，整页检测会误判为已盖章，局部检测则正确放行。

**Q：目标 PDF 是扫描件（整页一张图）？**
同样适用，`show_pdf_page` 会作为透明叠加层放在上层；只是 `verify` 的彩色检测可能受底图干扰。

**Q：页数变了 / 文件打不开？**
脚本用 `doc.save(tmp, garbage=3, deflate=True)` 再 `os.replace`，不会改页数；若打开异常，多半是原文件本身加密或损坏，用备份恢复后单独排查。
